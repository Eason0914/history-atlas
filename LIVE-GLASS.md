# Live map glass: stage-one prototype

The layout and integration described here remain the foundation. A subsequent [Qing-only optical refinement](GLASS-OPTICS.md) adds smooth six-pixel edge displacement, masked diffusion, directional light, adjustable tint and temporary A/B diagnostics. Navigation and the other preview materials retain the first-pass treatment described below.

Open [the prototype](https://eason0914.github.io/history-atlas/glass.html?prototype=live-map&unit=unit3). The regular `glass.html` and `classic.html` pages retain their existing layouts and direct marker-to-lesson behavior. Locally, run `python serve.py` and append `?prototype=live-map` to `glass.html`; direct-file opening works too.

## Design rationale

The existing information architecture stays intact: Explore map, Practice, Slide library, filters on the left, the interactive map, and the full study panel on the right. The prototype changes the map's visual extent and adds a lightweight preview step. Historical data, source images, TEA drafts, and review storage are shared with the existing site.

On desktop, the same interactive SVG map extends underneath the header and both side panels. Its initial camera fits the world into the unobscured center column. The title, comparison prompt, and legend remain in that column. On smaller screens, the existing stacked layout remains, with a sticky navigation bar and a preview card above the map.

| Surface | Treatment |
| --- | --- |
| Map foundation | Static Classic ocean `#e7ede7`, existing dot pattern, no ocean photograph or refraction. Slightly stronger land/coast contrast on desktop. |
| Navigation | Cool neutral tint, a narrow refractive bevel, one-pixel white highlight, restrained blue-gray shadow. |
| Marker preview | Same glass system with a stronger light tint behind its short summary. Dark blue text `#20334d`, muted text `#536980`. |
| Search/filter panel | Light reading surface with 6px blur on desktop; no displacement. |
| Full study panel | Nearly opaque reading surface; no displacement or blur applied to its text. |

The first pass intentionally uses strong live glass on only two components: the navigation bar and marker preview. Existing button styling is retained elsewhere. Opening animation lasts 160ms; there is no continuous decorative animation.

## Interaction

1. Click a marker, or focus it and press Enter/Space. A preview uses that entry's existing region, name, dates, and summary. It does not replace the full lesson yet.
2. Pan or zoom the map. The card follows its marker using actual screen coordinates. Candidate positions avoid side panels, screen edges, and zoom controls. A marker leaving the visible map dismisses its preview.
3. Select **Expand study notes** to update and focus the existing right-side panel. Source references, notes, TEA, MCQ distinctions, and drafts continue to use the original implementation.
4. Dismiss with the close button, Escape, or a click outside the card. Escape/Close restores marker focus. Dragging the map keeps the card open. Filtering away the marker or changing the main view dismisses it.

The preview is a nonmodal dialog, with no focus trap. Optical layers are `aria-hidden`, inert, and ignore pointer events. All visible preview text comes from `data.js`; no historical material is generated by the effect.

## Implementation

- `live-glass.css`: selectors opt in through `data-map-prototype=live`; normal editions are unaffected. Desktop map layering and the two glass components live here.
- `live-glass.js`: activates only for `?prototype=live-map`. `LiveGlassPane` owns a component's filter, optical layers, and size updates. Separate functions handle the camera and preview positioning.
- `app.js`: three small integration events: cancelable `atlas:marker-activate`, `atlas:open-entry`, and `atlas:entry-selected`. Without a preview listener, marker activation immediately opens the existing lesson, as before.
- `index.html`: loads the additional files; `tools/generate_editions.py` continues generating both editions.

### Actual live refraction

Chromium uses an SVG displacement filter as a **backdrop filter**. Its input is the browser's live composited content behind the pane, including the moving map. The pane's text is a separate foreground layer and is never distorted. This is different from applying a filter to a decorative background image.

Each pane generates a small rounded-rectangle surface-normal texture when its size changes. Refraction is strongest in a 16px bevel and neutral in the center. The maximum displacement is seven CSS pixels; specular highlights and tint are separate layers. The texture encodes displacement directions, not a picture of the map.

There are no map screenshots, remote textures, WebGL scene recreation, or runtime dependencies. Native backdrop updates are handled by the compositor. JavaScript uses mutation/resize/scroll events and one coalesced animation-frame callback for camera and card alignment; it does not run a perpetual render loop. Displacement textures are capped at 1,000 pixels wide and are regenerated only when component size changes.

### Practical fallback and limitations

SVG URL filters in `backdrop-filter` are not consistently supported across engines. The prototype selects the native route for Chromium and provides a **map-specific SVG fallback** elsewhere. The fallback references the original live `#map-world` with `<use>` and applies ordinary SVG displacement to a screen-aligned crop. It follows the same markers, visibility, pan, and zoom; it is not a static image or a deep clone of the page. It adds no duplicate interactive elements or IDs.

The fallback reproduces map content, not arbitrary HTML behind a pane. It is therefore suitable for these two components over the map, rather than a general solution for refracting every kind of webpage. Practice and Slide library use their original headers. Use `&glassRenderer=svg` to exercise this fallback in Chromium.

Reduced transparency and forced colors replace the optical layers with an opaque surface. Reduced motion disables card/button animation while retaining necessary marker tracking. A missing 2D canvas context also produces an opaque fallback.

Native refraction, forced SVG fallback, keyboard actions, direct-file opening, and responsive layouts were verified in Chrome on Windows. Mobile checks use browser emulation. Safari and Firefox physical-device behavior remains unverified; their fallback is implemented, not certified by those checks.

References: [the user's Liquid Glass reference](https://github.com/archisvaze/liquid-glass), [MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter), [MDN feDisplacementMap](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap), and [WebKit's SVG backdrop-filter issue](https://bugs.webkit.org/show_bug.cgi?id=245510). The implementation is original; no reference-demo application code or imagery is bundled.

## Validation and next stage

The first pass has 28 focused browser checks, including an actual pixel comparison of displacement enabled/disabled over a temporary pattern inside the live map. The temporary test pattern is removed and is not shipped. All 43 existing content, draft, quiz, image, library, and responsive checks also pass.

This prototype establishes the effect and interaction before broader changes. The next stage can reuse `LiveGlassPane` for zoom controls and a small selection of actions, after evaluating this version's appearance and performance. Long reading panels should retain their quieter surfaces. No second-stage expansion is applied to the normal editions in this change.
